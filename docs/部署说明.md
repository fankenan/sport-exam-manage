# 本机部署说明

> 面向本机（Windows）的完整部署与使用手册。

---

## 一、环境说明

| 组件 | 版本 | 位置 |
|---|---|---|
| Node.js | v24.20.0 | `C:\Program Files\nodejs` |
| MySQL | 8.0.43 (Windows x64 免安装版) | `D:\mysql-8.0.43` |
| 后端 | Express 4 + mysql2 | `D:\code\sport-exam-manage\server` |
| 前端 | Vue 3 + Element Plus + Vite | `D:\code\sport-exam-manage` |

后端在启动时会自动托管 `dist/` 里的前端构建产物，**只需要启动一个服务**。

---

## 二、启动

### 方式一：一键启动（推荐）

```bat
scripts\start-all.cmd
```

脚本会依次完成：启动 MySQL → 检查前端构建产物（缺失则自动构建）→ 启动后端。

启动后访问 **http://127.0.0.1:4000**

### 方式二：手动分步

```bat
:: 1. 启动 MySQL
"D:\mysql-8.0.43\bin\mysqld.exe" --defaults-file="D:\code\sport-exam-manage\server\scripts\my.ini" --console

:: 2. 构建前端（首次或代码有改动时）
cd /d D:\code\sport-exam-manage
npx vite build

:: 3. 启动后端
cd /d D:\code\sport-exam-manage\server
node index.js
```

### 停止服务

```bat
scripts\stop-all.cmd
```

## 四、数据库

- 库名：`sport_manage`，字符集 `utf8mb4`
- 连接账号：`sport_app`，口令写在 `server/.env` 的 `DB_PASSWORD`（该文件在 .gitignore 里，不入库）
- 配置文件：`server/scripts/my.ini`
- 数据目录：`D:\mysql-8.0.43\data`

表清单：

| 表 | 说明 |
|---|---|
| `grade_seven` / `grade_eight` | 七、八年级成绩（合计校对由 `server/derived.js` 统一计算） |
| `grade_nine` | 九年级成绩，报名序号存在 `student_number` 列 |
| `admission` | 中招体育成绩，报名序号存在 `registration_number` 列 |
| `grade_nine_registrations` | **九年级报名名单**（含原始行 JSON，供考务编排复用） |
| `grade_submissions` | 学校成绩上报单（七/八年级） |
| `app_settings` | 键值配置，目前存 `school_export_tables`（学校端导出授权） |
| 其他 | `users`、`schools`、`operation_logs`、`reconsiderations`、`materials`、`duplicate_records` |

`grade_nine_registrations` 与 `app_settings` 由 `server/db.js` 在启动时 `CREATE TABLE IF NOT EXISTS` 自动建好，
并写入默认导出授权 `grade_nine,admission`，**不需要手工执行 SQL**。

常用命令：

```bat
:: 命令行进入数据库
"D:\mysql-8.0.43\bin\mysql" -u sport_app -p -h 127.0.0.1 sport_manage

:: 备份
"D:\mysql-8.0.43\bin\mysqldump" -u sport_app -p sport_manage > backup.sql

:: 恢复
"D:\mysql-8.0.43\bin\mysql" -u sport_app -p sport_manage < backup.sql
```

```bat
cd /d D:\code\sport-exam-manage\server
node scripts\smoke-test.js
node scripts\test-registration.js
```

冒烟测试是自给自足的：运行时自建「冒烟测试中学」与专用账号 `smoke_school`、写自己的基线数据，

## 五之二、两个角色的操作路径

系统把「成绩导入」合并成了一个页面，按角色呈现两种落点：

### 管理员

1. 侧边栏 → **成绩导入**
2. 直接上传 Excel（**年级自动识别**，可混合七/八年级、可多校合并）
3. 点「校验并预览差异」→ 看到 新增 / 更新 / 无变化 三个数字与逐条差异
4. 点「确认导入」→ 直接写入正式成绩表，并记入操作日志
   - 若存在更新项，可改选「仅导入新增，更新项暂存到待处理」，在**成绩审核 → 重复处理**里后续处理
   - **若校验发现错误**：先点「导出错误清单」，再点「仅导入正确数据」—— 出错的行整行跳过，其余照常导入，剩下的改完再传一次即可
   - 学校账号没有「仅导入正确数据」这个选项，必须整批改对再提交

九年级走另一条路（教育局统一导入成绩，学校只报名）：

5. 侧边栏 → **报名审核** → 审核学校上报的报名名单（单条通过 / 多选批量通过 / 驳回）
6. 点「导入九年级成绩」→ 上传成绩表 → **先预检**（按身份证号匹配名单、核对性别↔长跑项目与球类项目），确认后再写库

   也可以直接从 **九年级成绩** 列表页右上角点「导入九年级成绩」，会落到同一个导入页的九年级模式。
7. 通过后成绩同时写入 `grade_nine` 与 `admission`

### 学校账号

1. 侧边栏 → **成绩导入**
2. 先选 **毕业年份** 与 **上报年级**，点「下载上报模板」按模板填写
3. 上传 Excel → 点「预检数据」→ 逐条查看差异与错误
4. 点「提交上报」→ 进入管理员的**上报审核**队列
5. 页面底部「我的上报记录」可查看状态与驳回原因

**九年级（上报报名信息）** 选中的是报名模式：

1. 点「下载报名表模板」→ 填 `学校 / 姓名 / 性别 / 身份证 / 报名序号 / 毕业年份 / 年级 / 项目1~5 / 备注`
2. 上传 → 点「预检报名信息」→ 服务端校验证件号、性别 ↔ 身份证第 17 位、性别 ↔ 长跑项目（男 1000 米 / 女 800 米）、球类只能是足球或篮球
   - 备注写 **病免 / 残免 / 弃考** 的学生不要求填任何项目，但仍需姓名、身份证、报名序号
3. 点「提交报名信息」→ 进入**报名审核**队列；下方「我的报名记录」可查看状态与驳回原因

> **学校账号没有任何直接写正式成绩表的入口** —— 这条不变量由后端强制，并有冒烟测试守护。
> 管理员侧同样不能走「提交上报」通道，管理员一律直接导入。
> 九年级成绩只能由管理员导入（「报名审核 → 导入九年级成绩」或「九年级成绩 → 导入九年级成绩」），学校端不提供成绩上传入口。
>
> **中招体育成绩页不再有「上传名单」入口** —— 名单由九年级报名审核通过时自动写入两张成绩表，「匹配成绩」按钮只负责把七/八年级分数汇总进来。

### 学校端导出授权

- 默认允许学校导出 **九年级成绩** 与 **中招体育成绩**（`app_settings.school_export_tables = 'grade_nine,admission'`）。
- 管理员在 **系统管理 → 学校端导出权限** 勾选/取消并保存，**立即生效**：
  未勾选的表，学校端列表页不渲染「导出Excel」按钮；直接调 `POST /api/data/export` 会返回 `403`。
- 管理员自己不受此开关限制。

## 八、常见问题

**Q：提示 `ECONNREFUSED 127.0.0.1:3306`**
MySQL 没启动。运行 `scripts\start-all.cmd`，或手动执行第 2 节的方式二第 1 步。

**Q：登录提示「登录状态已失效」**
修改密码后旧令牌会被立即吊销（安全设计），重新登录即可。

**Q：生产部署要注意什么**
1. 把 `server/.env` 里的 `JWT_SECRET` 改成 32 位以上的随机串
2. 把 `NODE_ENV` 改成 `production` —— 此时系统**不会**再自动创建 `admin/admin123`，
   而是在 `server/.initial-admin-password` 生成一次性初始口令
3. 把 `CORS_ORIGINS` 改成实际的前端域名
4. 给 `server/uploads/` 目录做磁盘容量监控
5. 数据库账号改用最小权限（不要 `ALL PRIVILEGES`）
